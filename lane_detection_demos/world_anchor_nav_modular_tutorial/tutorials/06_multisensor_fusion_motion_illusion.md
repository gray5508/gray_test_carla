# 06 多传感器融合与“箭头倒退”的感觉

严格说，这个 demo 当前没有真正融合 IMU、GNSS、LiDAR、Radar 等多种传感器。它主要使用：

- RGB 相机图像：给 YOLOP 做车道感知。
- CARLA 车辆 transform：知道车辆当前在世界中的位置和姿态。
- CARLA 相机 transform：知道相机当前在世界中的位置和姿态。

但它已经包含多传感器融合系统里很核心的一种思想：感知结果不能永远停留在图像像素中，必须落到一个稳定的空间参考系里。

## 为什么车动时箭头像在倒退

假设车辆前方 12 米处生成了一个箭头。锁定那一刻：

```text
车辆局部坐标中的箭头
  -> 通过 vehicle.get_transform()
  -> 转成 CARLA 世界坐标中的箭头
```

之后车辆继续向前开：

- 车辆坐标系变了。
- 相机坐标系变了。
- 但是箭头的世界坐标没变。

每一帧重新投影时，相机会从新的位置“看”同一个世界箭头。于是你会看到箭头逐渐靠近画面底部，像被车开过去一样。这不是箭头真的倒着动，而是自车前进造成的相对运动。

## 和真实自动驾驶的关系

真实系统里通常会有：

- 相机：识别车道、交通灯、标志、障碍物。
- IMU：提供短时间姿态和加速度变化。
- 轮速/里程计：估计车辆运动。
- GNSS/地图：提供全局位置或道路拓扑。
- LiDAR/Radar：提供更稳定的空间距离信息。

融合的目标是把不同来源的信息统一到一个坐标系中。例如：

```text
相机检测到的车道线
  -> 估计到车辆局部坐标
  -> 与车辆位姿融合
  -> 放到世界/地图坐标
  -> 给规划和可视化使用
```

本教程里的世界锚点箭头就是这个思想的简化版。

## pass 过期模式

参数 `--world-anchor-expire-mode pass` 表示：不要按固定时间消失，而是当车辆真的开过箭头参考点之后再清除。

相关函数：

- `WorldArrowAnchorTracker.pass_reference_world()`：选择用箭头起点、中心点还是终点作为“是否开过”的参考。
- `world_point_to_vehicle_local()`：把这个世界点转换到当前车辆局部坐标。
- `has_vehicle_passed_anchor()`：如果参考点已经落到车辆后方，就认为车辆开过了箭头。

## 学习任务

1. 使用默认 `--world-anchor-expire-mode pass`，观察车辆开过箭头后箭头消失。
2. 改成 `--world-anchor-expire-mode time`，观察箭头只按时间过期。
3. 分别试 `--world-anchor-pass-point start`、`center`、`target`，观察箭头清除时机不同。
4. 思考：如果以后加入 IMU 或 GNSS，哪些地方可以替换 CARLA 的真实 transform？
